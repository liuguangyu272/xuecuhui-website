# 内容台中的材料协作

入口为 `/console.html`。沿用内容台现有管理口令，不创建姓名／学号账号，不设置部长／成员个人权限。任务的材料负责人、美工负责人为姓名文字；操作人姓名是填写记录，不是已认证身份。任何持有内容台口令的维护者都可分配、提交和审核。

## 页面

- 任务与审核：填写操作人，分配材料任务、指定负责人、截止日期、参考模板，可选择需要美工处理或更新已有正式资料。
- 正式资料归档：检索、下载正式文件，查看保留的旧文件，上传已有正式资料，发布到学生资料库。
- 要求与模板：编辑材料要求，上传、下载模板。

## 工作流程

分配任务 → 材料负责人上传实际文件和修改说明 → 审核通过或退回 → 如需美工，交给指定美工负责人上传新成果 → 再次审核 → 正式资料归档。

退回必须填写意见，可重复提交；待审核和已归档任务不能再次直接上传。每次审核只允许处理一次。更新已有资料时，待审稿不改变当前正式文件；审核通过时可选择保留旧文件，默认不保留。不提供文件差异比较或恢复操作。

归档后点击「发布到学习小站」，选择已有年级和学科。发布时将文件复制到公开 `assets/docs/` 并更新原有 `library.docs`，已有公开版复用资料 ID，不重复新增。Markdown/PDF 自动适用现有阅读器。其他格式沿用资料库下载能力。

## 数据边界

内部数据库和工作文件位于 `/var/lib/xuecuhui-materials/`，可通过 `MATERIALS_STATE` 配置。目录不在网站静态根目录和仓库内；待审文件和模板只通过要求 `X-Token` 的接口下载，不写入 `/api/data` 或 CMS 公开快照。上传支持现有文档和图片类型，最大 50MB，沿用文件头校验。

只有明确发布的正式文件进入公开目录和 CMS GitHub 同步。旧的公开副本继续保留，避免破坏正在阅读或其他内容已引用的文件；「不保留旧文件」删除的是被替换的内部正式版本。内部数据库、内部文件需纳入服务器数据备份，代码回滚不恢复业务数据。

发布与原 CMS 使用同一内容锁；快照入队失败会恢复发布前的公开目录记录。现有后台页面仍采用原认证设计，本次没有新建个人登录系统。

## 验证

后端隔离 HTTP 测试：`python3 services/upload/test_materials.py`。

浏览器隔离测试：先运行 `python3 services/upload/test_materials.py --serve`，将输出的本机 URL 设置为 `MATERIALS_QA_URL`，运行 `node deploy/test_materials_ui.cjs`。可通过 `PLAYWRIGHT_MODULE` 指向本机 Playwright，`MATERIALS_QA_DIR` 保存截图。测试限制为 127.0.0.1，避免在生产创建测试任务或发布资料。
